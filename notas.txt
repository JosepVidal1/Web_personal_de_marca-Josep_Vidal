# Notas del proyecto: Web personal de marca

## 1. Objetivo

Añadir a mi web personal una sección que muestre información de mi perfil de GitHub utilizando su API pública, sin necesidad de iniciar sesión ni utilizar un token de autenticación.

## 2. Cambios realizados

1. He creado el archivo `api.js` para gestionar la consulta a la API de GitHub.
2. He añadido una sección con el identificador `github` en `index.html`.
3. He enlazado el archivo `api.js` desde `index.html`.
4. He añadido estilos en `style.css` para mostrar la información en una tarjeta, adaptarla a móviles e integrarla con el modo oscuro.
5. He utilizado `fetch()` para solicitar los datos del perfil de GitHub.
6. He utilizado `async/await` para gestionar la petición y `try/catch` para controlar posibles errores.
7. He preparado la actualización automática de los datos cada 600 segundos (10 minutos).

## 3. Datos que se quieren mostrar

La consulta utiliza la API pública:

https://api.github.com/users/JosepVidal1

Los datos previstos son:
- Nombre de usuario de GitHub.
- Número de repositorios públicos.
- Número de seguidores.
- Enlace al perfil de GitHub.

## 4. Tecnologías utilizadas

- HTML5 para la estructura.
- CSS3 para el diseño adaptable.
- JavaScript para consultar y mostrar los datos.
- API REST pública de GitHub.
- JSON para recibir y procesar la información.

## 6. Diseño y adaptación

Se ha preparado el widget para mantener la coherencia visual con la web personal, adaptarse a pantallas móviles y respetar el modo claro y oscuro.

## 7. Errores y mejoras pendientes

# Notas del proyecto: Web personal de marca

## Widget API: datos vivos de GitHub

### 1. Frase de marca (por qué este widget)

Mi web va de mi camino como futuro programador (DAM, automatización, IA) y por eso
muestro mis datos reales de GitHub: mis repositorios públicos y mis seguidores.
No digo "programo", lo demuestro con números que crecen solos cada vez que subo un proyecto.

### 2. Variante elegida

- Variantes valoradas: (A) tarjeta con métricas, (B) línea de texto "X repos · Y seguidores",
  (C) medidor de progreso de repos.
- Elegida: (A) TARJETA, porque encaja con el diseño de tarjetas que ya uso en "Me gusta"
  y con la paleta sobria de mi marca (#273746).

### 3. Datos técnicos

- API: https://api.github.com/users/JosepVidal1 (pública, sin clave, sin token).
- CORS: la respuesta incluye la cabecera `access-control-allow-origin: *`.
- Archivo: api.js (cargado al final de index.html con <script src="api.js"></script>).
- Hueco en el HTML: <div id="widget"> dentro de la sección #github.
- Campos del JSON que se pintan:
  - avatar_url    -> foto redonda
  - name / login  -> nombre y @usuario
  - public_repos  -> número de repositorios públicos
  - followers     -> número de seguidores
  - html_url      -> enlace al perfil
- Recarga automática: cada 600 s (variable `segundosActualizacion` en api.js; 0 = desactivada).

### 4. Recorrido del dato (para la defensa)

1. Abro la web -> el navegador carga index.html y ejecuta api.js.
2. api.js pide la URL https://api.github.com/users/JosepVidal1 con fetch().
3. GitHub devuelve un JSON con todos mis datos públicos.
4. El código coge solo los campos que necesito (public_repos, followers...) y los pinta
   en el <div id="widget">.
   Si algo falla (sin internet, GitHub caído, límite 403) entra el try/catch y se muestra
   un mensaje amable, nunca un "Cargando..." eterno.

### 5. Estados del widget

- Cargando: tarjeta "esqueleto" gris que parpadea.
- Correcto: tarjeta con avatar, nombre, métricas, enlace y "actualizado a las HH:MM".
- Error sin datos previos: aviso amable + enlace directo a mi perfil.
- Error en una recarga: se mantienen los últimos datos y se avisa en la línea de actualización.
- Límite de GitHub (403, ~60 peticiones/hora por IP sin clave): mensaje específico.

  el esqueleto la primera vez.
