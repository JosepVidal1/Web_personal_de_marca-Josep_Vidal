# Notas del proyecto: Web personal de marca

## 1. Frase de marca

Mi web va de mi camino como futuro programador (DAM, automatización, IA) y por eso
muestro mis datos reales de GitHub: mis repositorios públicos y mis seguidores.
No digo "programo", lo demuestro con números que crecen solos cada vez que subo un proyecto.


## 2. Widget de GitHub: datos vivos de una API externa

### 2.1 Objetivo

Mostrar en mi web información real de mi perfil público de GitHub usando su API,
sin iniciar sesión y sin token ni clave.

### 2.2 Variante elegida

- Variantes valoradas: (A) tarjeta con métricas, (B) línea de texto "X repos · Y seguidores",
  (C) medidor de progreso de repos.
- Elegida: (A) TARJETA: título, descripción «Mi actividad como desarrollador.»,
  dos cifras destacadas y enlace al perfil. Encaja con el diseño de tarjetas del resto de la web.

### 2.3 Datos técnicos

- API: https://api.github.com/users/JosepVidal1 (pública, sin clave).
- Archivo: api.js, cargado al final de index.html con <script src="api.js"></script>.
- Hueco en el HTML: <div id="widget"> dentro de la sección #github.
- Campos del JSON que se pintan:
  - avatar_url    -> foto redonda
  - name / login  -> nombre y @usuario
  - public_repos  -> número de repositorios públicos
  - followers     -> número de seguidores
  - html_url      -> enlace al perfil
- Recarga automática: cada 600 s (variable `segundosActualizacion` en api.js; 0 = desactivada).
- Tecnologías: HTML5, CSS3, JavaScript, fetch(), async/await, JSON, try/catch, API REST.

### 2.4 Recorrido del dato (para la defensa)

1. Abro la web -> el navegador carga index.html y ejecuta api.js.
2. api.js pide la URL https://api.github.com/users/JosepVidal1 con fetch().
3. GitHub devuelve un JSON con todos mis datos públicos.
4. El código coge solo los campos que necesito (public_repos, followers...) y los pinta
   en el <div id="widget">.
   Si algo falla (sin internet, GitHub caído, límite 403) entra el try/catch y se muestra
   un mensaje amable, nunca un "Cargando..." eterno.

### 2.5 Estados del widget

- Cargando: tarjeta "esqueleto" gris que parpadea.
- Correcto: tarjeta con avatar, nombre, descripción, métricas, enlace y hora de actualización.
- Error sin datos previos: aviso amable + enlace directo a mi perfil.
- Error en una recarga: se mantienen los últimos datos y se avisa.
- Límite de GitHub (403, ~60 peticiones/hora por IP sin clave): mensaje específico.


## 3. Formulario de contacto (Formspree)

- Requisito mínimo de la rúbrica: un visitante debe poder contactarme de verdad.
- Decisión: formulario con Formspree en vez de publicar mi correo, para proteger mi
  privacidad. Formspree recibe el mensaje y me lo reenvía a mi correo real.
- Descarté usar el correo "noreply" de GitHub porque no es un buzón real:
  los mensajes no llegarían nunca (la rúbrica lo considera "mail inventado").
- Archivos: sección #contacto en index.html, estilos en style.css y lógica en contacto.js.
- Validación: campos obligatorios (required), correo con formato válido (type="email"),
  mensaje de 10 caracteres como mínimo.
- contacto.js envía los datos con fetch() y muestra un mensaje de éxito o de error
  sin salir de la web. Incluye un campo trampa (_gotcha) contra spam.


## 4. Errores detectados y corregidos

- La cuadrícula de "Me gusta" usaba `section:nth-of-type(3)`. Al añadir la sección de
  GitHub, "Me gusta" pasó a ser la 4ª y perdió el diseño. Corregido usando `#me-gusta`.
- La tarjeta de GitHub tenía colores fijos. Ahora usa las variables CSS de mi marca,
  así el modo oscuro se aplica solo.
- El menú no tenía enlace a GitHub ni a Contacto. Añadidos.
- Cada recarga automática borraba la tarjeta. Ahora el esqueleto solo sale la primera vez.
- Faltaba en style.css la clase `.solo-lectores` que usa api.js. Añadida.
